# Очистка дождевой воды и умный полив

Проект системы для сбора дождевой воды, её фильтрации и автоматического полива растений. По задуманной схеме Arduino Uno контролирует качество воды и влажность почвы, а клапаны управляют движением воды между резервуарами и подачей к растениям.

## Как устроена система

1. **Резервуар 1** собирает дождевую воду. Затем она проходит через механический фильтр.
2. **Резервуар 2** предназначен для контроля воды по показаниям датчиков TDS, мутности и pH. По схеме клапан 1 управляет переходом воды в следующий резервуар после фильтра второй ступени.
3. **Резервуар 3** хранит воду для полива. Датчики TDS, мутности и pH проверяют её качество, а клапан 2 подаёт воду к почве.
4. **Датчик влажности почвы** помогает определить, нужен ли полив.

Схема описывает всю предполагаемую систему. Сейчас в репозитории находится программа **только для клапана 2**; управление клапаном 1 и датчиками резервуара 2 в неё ещё не включено.

## Как работает программа полива

- При запуске Arduino проверяет влажность почвы.
- Если влажность достаточная, клапан 2 остаётся закрытым; следующая проверка выполняется через 10 минут.
- Если почва сухая, программа проверяет показатели воды в резервуаре 3. Когда все они находятся в заданных пределах, клапан 2 открывается на 20 секунд.
- Через 2 минуты после закрытия клапана программа снова измеряет влажность. Если почва всё ещё сухая и вода подходит для полива, цикл повторяется.
- Если вода выходит за заданные пределы, клапан остаётся закрытым, а следующая проверка выполняется через 10 минут.

## Подключение для текущего скетча

| Вывод Arduino Uno | Подключение |
| --- | --- |
| A0 | Аналоговый выход датчика влажности почвы |
| A1 | Аналоговый выход датчика TDS резервуара 3 |
| A2 | Аналоговый выход датчика мутности резервуара 3 |
| A3 | Аналоговый выход модуля pH резервуара 3 |
| D7 | Управляющий вход реле клапана 2 |

Это пример назначения выводов: подключение и питание зависят от конкретных датчиков, реле и клапана. Для закрытия при отключении питания используйте нормально закрытый клапан и подходящее подключение реле.

## Запуск и настройка

1. Откройте `Code/SmartWatering/SmartWatering.ino` в Arduino IDE, выберите плату Arduino Uno и нужный порт.
2. Проверьте назначение выводов и логику реле. По умолчанию в коде реле включается уровнем `LOW`; для модуля с активным `HIGH` поменяйте значения `RELAY_ON` и `RELAY_OFF`.
3. Откалибруйте датчик почвы: задайте разные значения `SOIL_DRY_ADC` и `SOIL_WET_ADC`, измеренные в сухой и влажной почве. Порог полива задаётся в `SOIL_MIN_PERCENT`.
4. Откалибруйте каждый датчик воды на двух эталонах и внесите показания АЦП и соответствующие значения в `TDS_CAL` (мг/л), `TURBIDITY_CAL` (NTU) и `PH_CAL` (pH). Две точки должны охватывать измеряемый диапазон; показания за его пределами отклоняются. Линейное преобразование применимо только если оно подтверждено для вашей модели датчика в этом диапазоне. Для TDS учитывайте температуру воды: выполняйте измерения при температуре калибровки или используйте предусмотренную производителем компенсацию.
5. Только после калибровки и проверки измените `WATER_SENSORS_CALIBRATED` на `true`. Пока флаг равен `false`, клапан 2 не откроется.
6. Загрузите скетч и откройте монитор порта со скоростью **9600 бод**, чтобы увидеть показания и сообщения о работе системы.

### Пороги воды

- TDS: **менее 450 мг/л** — ориентир для отсутствия ограничений по засолению ([источник](https://doiserbia.nb.rs/img/doi/0354-9836/2023/0354-98362304299E.pdf)).
- pH: **6,5–8,4** — типичный диапазон поливной воды ([Университет Флориды](https://ask.ifas.ufl.edu/publication/EP616)).
- Мутность: **менее 10 NTU** — предварительный порог для ограничения риска засорения, а не универсальная норма ([исследование водоснабжения](https://www.waterboards.ca.gov/water_issues/programs/grants_loans/water_recycling/research/02_011.pdf)). Мутность сама по себе не определяет риск засорения ([Университет Флориды](https://ask.ifas.ufl.edu/publication/ae032)).

Пределы зависят от растения, воды и системы полива. Эти три показателя не выявляют все возможные химические и микробные загрязнения и не подтверждают, что вода пригодна для питья. Значения почвы в коде остаются примером и требуют отдельной калибровки. Программа не может надёжно обнаружить все неисправности датчиков.
Редкое считывание датчика почвы само по себе не отключает его питание. Для экономии энергии его питание нужно коммутировать отдельно с учётом характеристик датчика; Arduino Uno при этом продолжает потреблять энергию.
